# Regex-строки для поиска в игре (S7)

> Задача: собрать строку для поля поиска игры (стэш, вкладка карт, торговец), которая подсвечивает нужные
> предметы. Источник требований — [PLAN-POETH.md](PLAN-POETH.md), раздел «Regex». **poe.re не используем:**
> у проекта нет лицензии — ни код, ни данные не копируем; движок и данные строим сами из открытых данных
> RePoE fork. Идеи (подход «кратчайшая уникальная подстрока») авторским правом не защищены.

## Синтаксис поиска игры (что эмулирует `emulator.ts`)

- Поиск идёт **без учёта регистра** по тексту предмета (имя, база, свойства, моды — то, что видно в подсказке).
- Термы через **пробел** — логическое **И** (каждый терм должен совпасть).
- `"…"` — терм с пробелами внутри; `|` внутри терма — **ИЛИ**: `"a|b"` = есть a или b.
- `!` в начале терма — **НЕ**: `"!a|b"` = нет ни a, ни b.
- Внутри терма работают регулярные выражения: `.`, `\d`, `[…]`, `(…)`, `?`, `+`, `*`; пример порога
  «≥ 80 %»: `([89].|\d..)%`.
- **Лимит — 250 символов** на всю строку. UI показывает счётчик и не даёт сохранить длиннее.
- ⚠ RU-клиент: регистронезависимость кириллицы и `ё`/`е` в поиске игры не проверены → токены строим из точного
  нижнего регистра текста мода, проверка в игре на Д10 (риск №6 плана).

## Данные (генератор, `tools/regex/build-regex-data.mjs`)

- Вход — RePoE fork: `mods.min.json`, `stat_translations.min.json`, `Russian/stat_translations.min.json`.
- Моды карт: `domain = area` (+ нужные generation types) → текст мода на EN и RU (с подстановкой значений
  вида `#` → диапазон).
- Для каждого мода ищем **кратчайшую уникальную подстроку** (с запасом по границам слов), которая:
  - встречается в тексте этого мода;
  - **не встречается** ни в одном другом моде домена и ни в одной строке подсказки карты
    (`tools/regex/extra-lines.{en,ru}.txt`: «Item Quantity», «Map Tier», «Corrupted», …) — проверка на ложные
    срабатывания.
- Выход — `resources/data/poe1/regex/{en,ru}.json` (`{modId, text, token, tier?}`), версия данных в meta.

## Движок (`src/shared/regex/`)

- `engine.ts`: на вход — наборы «хочу (любой из)», «не хочу», «обязательно», числовые пороги; на выход — строка.
  - нежелательные → один терм `"!a|b|c"`;
  - «любой из» → `"a|b|c"`;
  - «обязательно» → отдельные термы (И);
  - жадное покрытие: выбираем токены так, чтобы одна подстрока покрывала несколько выбранных модов
    (общий префикс/суффикс), пока не влезаем в 250 символов; при переполнении — понятная ошибка
    «уберите N модов» и подсказка, что выкинуть.
- `atLeast.ts`: `atLeast(n)` — регулярка «число ≥ n» для 0–999 (`80` → `([89].|\d..)`), тест на всех 0–999.
- `emulator.ts`: повторяет поиск игры (И/ИЛИ/НЕ/регэксп, без регистра) и проверяет готовую строку на всех модах:
  нужные совпадают, лишние — нет. Это главный тест движка.

## Страницы UI (вкладка Regex)

- **Карты:** моды «хочу / не хочу», количество предметов / размер стай / редкость / доп. карты / скарабеи / валюта
  (через `atLeast`), осквернённые / неопознанные.
- **Торговец:** линки, цвета сокетов, скорость передвижения, уровни камней.
- **Библиотека:** свои сохранённые строки, хоткеи вставки `pasteSearch1..5` (Ctrl+F → вставить в поле поиска).

## Тесты (`tests/regex/**`)

- каждый токен совпадает **только со своим** модом (EN и RU);
- `atLeast(n)` корректен для всех 0–999;
- выход движка через `emulator` без ложных срабатываний и ≤ 250 символов на случайных наборах модов.
