# Regex-строки для поиска в игре (S7)

> Задача: собрать строку для поля поиска игры (стэш, вкладка карт, торговец), которая подсвечивает нужные
> предметы. Источник требований — [PLAN-POETH.md](PLAN-POETH.md), раздел «Regex». **poe.re не используем:**
> у проекта нет лицензии — ни код, ни данные не копируем; движок и данные строим сами из открытых данных
> RePoE fork. Идеи (подход «кратчайшая уникальная подстрока») авторским правом не защищены.

## Синтаксис поиска игры (что эмулирует `src/shared/regex/emulator.ts`)

- Поиск идёт **без учёта регистра** по тексту предмета (имя, база, свойства, моды — то, что видно в подсказке).
- Термы через **пробел** — логическое **И** (каждый терм должен совпасть).
- `"…"` — терм с пробелами внутри; `|` внутри терма — **ИЛИ**: `"a|b"` = есть a или b.
- `!` в начале терма — **НЕ**: `"!a|b"` = нет ни a, ни b.
- Внутри терма работают регулярные выражения: `.`, `\d`, `\w`, `[…]`, `(…)`, `?`, `+`, `*`, `{n}`, `$`.
- Эмулятор считает, что строки подсказки разделены `\n`, «.» не переходит через строку, `$` — конец строки.
- **Лимит — 250 символов** на всю строку. UI показывает счётчик и не даёт сохранить/скопировать длиннее.
- Опции эмулятора для непроверенного поведения игры: `foldYo` (ё = е) и `asciiCaseOnly` (регистр важен
  для кириллицы). Тесты гоняют токены во всех режимах.

## Данные (`tools/regex/build-regex-data.mjs`)

```bash
node tools/regex/build-regex-data.mjs                    # из кэша tools/regex/sources/ (в .gitignore)
node tools/regex/build-regex-data.mjs --refresh --patch 3.30   # новый патч: перекачать и пересобрать
```

- Вход — RePoE fork: `mods.min.json`, `stat_translations.min.json`, `Russian/stat_translations.min.json`,
  `base_items.min.json`, `Russian/base_items.min.json`. Дата данных в `meta.date` — Last-Modified источников
  (сборка детерминированная: те же источники → байт-в-байт те же файлы).
- Моды карт: `domain = area`, `prefix/suffix` с весом > 0 для тегов карт (default, *_tier_map, uber_tier_map,
  has_uber_map_*, maven_*); логбуки и вааль-зоны отброшены; осквернённые имплиситы (`generation_type =
  corrupted`) — тоже в списке, `kind: implicit`. Моды только кошмарных карт — тег `t17`.
- Текст мода — через stat_translations: числа → `#`, нижний регистр, разметка `[Ключ|Текст]` снята; скрытые
  статы (IIQ/IIR/pack size карты, «# patches with Ground Effect…») не показываются в подсказке и отброшены.
  Моды с одинаковым видимым текстом (тиры, Maven-варианты) склеены; `id` = видимые stat id — общий для EN и RU.
- Для каждого мода — **кратчайшая уникальная подстрока** (обычно 2–12 символов, в среднем ~3.5):
  - не встречается ни в одном другом моде (кроме «надмножеств» — модов, где есть все строки этого мода)
    и ни в одной строке подсказки карты (`tools/regex/extra-lines.{en,ru}.txt` + базы карт, «Blighted …»,
    влияния из RePoE);
  - проверка «со свёрткой» ё→е; в RU — без букв, которые в подсказке заглавные; без спецсимволов, если можно;
  - число внутри токена — `\d+` (только если у стата нет дробных обработчиков).
  - Если уникальной подстроки нет (составные моды T17, все строки которых есть в других модах), токен
    помечен `alsoMatches` — UI предупреждает «заденет и …».
- Метки порогов (`labels`: quantity, packSize, rarity, moreMaps, moreScarabs, moreCurrency, moreDivCards) и
  флаги (`flags`: corrupted, unidentified — с `$`) ищутся тем же алгоритмом, с предпочтением двоеточия.
- Выход — `resources/data/poe1/regex/maps.{en,ru}.json`:
  `{meta:{source,date,patch,lang}, mods:[{id,text,display,token,kind,tags,scary?,alsoMatches?}], labels, flags, extra}`.
  Main отдаёт их через IPC `regex:mapData` (сначала `userData/data/poe1/regex/` — обновление без переустановки).

## Данные «Торговца» (S27, `tools/regex/build-vendor-data.mjs`)

```bash
node tools/regex/build-vendor-data.mjs                    # из того же кэша tools/regex/sources/
node tools/regex/build-vendor-data.mjs --refresh --patch 3.30
```

- Что ищет поиск игры (PoE 1, с 3.14): каждую строку текста предмета как при Ctrl+C, без учёта регистра —
  в том числе «Item Class: Boots» и «Rarity: Magic» (RU: «Класс предмета: Обувь», «Редкость: Волшебный»).
  Поэтому класс и редкость — фильтры «И».
- Вход: RePoE fork (`mods`, `stat_translations` EN/RU, `base_items` EN/RU, `item_classes` EN/RU), client_strings
  APT (`resources/data/poe1/{en,ru}`), строки фикстур парсера `tests/fixtures/poe1/{en,ru}` (кроме `adv-*`).
- 39 свойств (`PROPS`): жизнь, мана, ES; сопротивления (одиночные + двойные, как у Two-Stone Ring), «ко всем
  стихиям», хаос; «+ к уровню камней» по типам (все, чары, огонь, холод, молния, хаос, физ., приспешники, лук,
  ближний бой); урон чар, физ. урон оружия, стихийный урон атак; добавленный урон к атакам (кольца, перчатки,
  колчаны + на оружии) и к чарам; скорость передвижения, атаки, чар, шанс крита; сила, ловкость, интеллект,
  «все характеристики». Свои строки — по stat id через stat_translations (`text` — с исходным регистром).
- Корпус «чужих» строк: моды предметов торговца и тайника (`item`/`crafted`/`flask`: префиксы, суффиксы,
  осквернённые, имплиситы Пожирателя/Экзарха и баз), метки свойств, классы, редкости, названия баз, строки
  фикстур. Зачарования лабиринта не входят (у торговцев их нет).
- Порог «≥ N»: `<pre><atLeast(N)><post>` — `post` кратчайшее начало текста после числа, `pre` — конец текста
  до числа, если без него не обойтись (`\+` отсекает «-#% to fire resistance»); с `pre` число берётся целиком
  (`atLeast(n, {whole: true})`). Без порога — кратчайшая подстрока или `a.*b` (в RU порядок слов «к уровню
  размещённых камней огня» / «к качеству размещённых камней огня»). Класс и редкость — метка с «:»; в RU
  заглавная буква значения заменена на «.» (регистр кириллицы в игре не проверен).
- `^` и `$` не используем. Что неизбежно задевается, помечено: `also` — свои строки другого свойства
  («Adds # to # Fire Damage» на оружии — начало «… to Spells»; в RU «+1 к уровню размещённых камней» — начало
  строк с типом), `side` — `minions` («Minions have …»), `negative` (та же строка с минусом), `gems` (описание
  камня-проклятия). UI показывает это предупреждением «Строка также подсветит …».
- Выход: `src/shared/regex/vendorData.ts` (генерируется, в репозитории) и корпус для тестов
  `tests/regex/fixtures/vendor-corpus.{en,ru}.json`.

## Движок (`src/shared/regex/`)

- `atLeast.ts`: `atLeast(n)` — «число ≥ n» для 0–999 (`80` → `([89].|\d..)`, `85` → `(8[5-9]|9.|\d..)`,
  `100` → `[1-9]..`); в контексте `<метка>.*<atLeast>%` длинные числа совпадают «хвостом». Вариант
  `{digit:'\\d'}` — когда после числа нет «%» («Level: 20»).
- `cover.ts`: жадное покрытие выбранных модов общими подстроками (без задевания невыбранных модов и строк
  подсказки); берётся короче из «покрытие» и «токены по отдельности».
- `maps.ts`: не хочу → `"!a|b|c"` (+ исключённые флаги), хочу любой → `"a|b"`, хочу все → отдельные термы,
  пороги → `"<метка>.*<atLeast>%"`, только осквернённые/неопознанные → терм флага. При > 250 — `overflow`
  `{by, suggest}` (что убрать). `sideMatches` — невыбранные моды, которые строка заденет.
- `vendor.ts`: линки `-\w-` (3) … `-\w-.-.-.-` (6), R-G-B, `N` гнёзд цвета в связке `b(-\w)*-b`, 6 гнёзд,
  качество `ality:.*<n>%` / `ество:.*<n>%`, любой «+ к уровню камней», уровень камня (отдельное «И» + исключение
  строки «Item Level» из данных: `"!m level:"` / `"!ь предмета:"` — в RU раньше ловилось «Уровень: 64» в
  требованиях); S27 — свойства `mods` (`vendorModPattern`), класс и редкость (отдельные «И»), готовые наборы
  `VENDOR_PRESETS` (старт лиги: ботинки со скоростью, кастер, атака, сопротивления). Скорость передвижения —
  `mods.moveSpeed` (поле `movementSpeed` до S27 библиотека переносит).
- `presets.ts`: готовые строки для новичков (строятся движком под язык клиента), `library.ts`: библиотека
  (нормализация, слоты 1–5, экспорт/импорт) — чистые функции.

## UI (вкладка Regex) — по утверждённому макету «Золото компаса»

Макет: https://claude.ai/artifact/MXRL1ZdMzJtoLeeHkgXRTW (раздел «Компаньон: Regex»), компоненты `ui-*` из
`styles/components.css`, правила — [design-system.md](design-system.md). Свой CSS (`panels/regex/regex.css`) — только
раскладка на токенах; иконки — спрайт `resources/brand/icons-sprite.svg` (`panels/regex/Ico.tsx`).

- Сверху: подвкладки `ui-tabs` «Карты / Торговец / Библиотека» (у библиотеки `ui-count`), справа **язык игры**
  (как интерфейс / RU / EN) и переключатель **«Экспертный режим»** (`settings.ui.simpleMode`, общий для приложения).
- Справа на «Картах» и «Торговце» — блок «Строка для поиска в игре»: моноширинная строка (лигатуры шрифта
  выключены), `ui-meter` (зелёный до 200, жёлтый до 250, красный — длиннее, с подсказкой что убрать),
  «Копировать» (`--primary`), «В библиотеку» (с названием), «Сбросить»; предупреждение о побочных совпадениях.
- **Карты:** поиск и чипы (Все / Опасные / Выбранные, в экспертном ещё T17 / Ваал), легенда «Клик переключает»,
  моды `ui-tri`: клик неважно → хочу → не хочу, ПКМ — сразу «не хочу»; пометки ⚠ (причина в подсказке), T17, Ваал,
  ≈ (неуникальный токен); в экспертном режиме — токен мода. Пороги «≥ %» (простой режим — 4, экспертный — 7),
  «Хочу: все сразу / любой из» (по умолчанию «все сразу» — отдельные термы, как в заметке к макету),
  осквернённые и неопознанные (Любые / Только / Без).
- **Торговец:** «Готовые наборы» (чипы, в простом режиме — описание выбранного), связи (—/3L…6L), R-G-B,
  «любое / все сразу»; в экспертном — 6 гнёзд, N гнёзд цвета, качество ≥ %, уровень камня. «Свойства предметов»:
  класс (`Select`) и редкость (чипы), в простом режиме — «Главное на прокачке» (скорость, здоровье),
  сопротивления, «+ к уровню камней»; в экспертном — все группы. Пороги — строка «подпись ≥ число %», без
  порога — чипы; в подсказке строки — текст мода на языке клиента игры.
- **Библиотека:** баннер «Как вставлять», пять слотов горячих клавиш (`ui-kbd` из настроек хоткеев или «Слот N»,
  свободный слот — подсказка), строки без клавиши, новая/изменить (со счётчиком 250), экспорт/импорт, готовые
  строки для новичков. Файл — `%APPDATA%/POETH/regex-library.json` (атомарная запись), экспорт
  `{format:'poeth-regex', version:1, entries}`.
- Хоткеи `pasteSearch1..5`: текст слота даёт `getPasteString(slot)` (`src/main/ipc/regex.ts`) — подключается
  к `stashSearch()` из S1.

## Тесты (`tests/regex/**`)

- `atLeast` — перебор n 0–999 × v 0–999 (+ длинные числа для n < 100, вариант `\d`);
- каждый токен совпадает только со своим модом (и надмножествами/`alsoMatches`), не задевает строки подсказки
  — EN и RU, с ё=е и без, RU — даже при регистрозависимой кириллице;
- движок через эмулятор на синтетических подсказках карт: без ложных срабатываний, ≤ 250 символов на
  типовых наборах (10 «плохих» модов + 3 порога), случайные наборы, пороги, флаги, переполнение;
- торговец (линки, цвета, скорость, качество, камни) EN/RU; библиотека и пресеты.
- свойства торговца (`vendorMods.test.ts`): каждое из 39 свойств EN/RU совпадает со своей строкой (пороги — на
  значениях 1…230) и не задевает строки корпуса, кроме вариантов, `also` и `side` (ё=е, регистрозависимая
  кириллица); настоящие фикстуры; классы и редкость; наборы ≤ 250 символов; переполнение и «что убрать».

## Проверить в игре (Д10)

1. RU-клиент: регистронезависимость кириллицы (токены подобраны без заглавных букв — должно работать в любом
   случае) и **ё/е** (`осквернённые` vs `оскверненные`; токены проверены «со свёрткой»).
2. `.` не переходит через строку подсказки (иначе пороги `метка.*число%` могут ложно сработать на соседней
   строке), `$` — конец строки (флаг «осквернено» `pted$`/`нено`).
3. Поддержка `\w` (линки `-\w-.-`) и `\d+` в токенах.
4. Уровень камня: строка требований («Requires Level 70» / RU) не должна совпадать с `evel: N`.
5. Тексты «Торговца» в RU: «повышение скорости передвижения», «Качество:», «к уровню».
6. S27: строки «Item Class: …» / «Rarity: …» ищутся поиском у торговца (фильтр «ботинки», «волшебный»);
   `.` вместо заглавной буквы в RU-метке («: .бу» для «Обувь»); `a.*b` в RU-токенах камней («вню.*гн»).
